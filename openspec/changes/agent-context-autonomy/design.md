# Design: agent-context-autonomy

> 配套 `proposal.md`。agent 会话上下文自治：框架保证单一硬 T，T 内工作集由模型自决策；四区硬比例仅保留在框架查询路径。

## Context

- `MemoryAgent.chat` 现状：messages 只增不减，工具结果全文常驻；无会话级预算（只有 summary_budget 管图摘要注入、max_turns 管轮次）。实测 127K token/题（multihop）。
- 框架查询管线的四区模型（积累区 token_budget 封顶 / 活跃区取余 / visited-frontier id 簿记）是静态分配——为无判断力的 BFS 循环设计。
- 图特性：任何被逐出的内容可按 `[id:...]` 经 search/associate 取回——**遗忘可逆**，这是本设计可行的结构前提（通用 agent 无此保障）。

## Goals / Non-Goals

**Goals**
- token/题 显著下降（目标 ≥50%），reached 不降、超轮次失败不增（A/B 硬门槛）。
- 取舍决策权归模型（pin/换出），总量硬保证归框架（会话层铁律一）。
- 全程可观测（每次折叠/逐出/pin 入 trace）。

**Non-Goals**
- 不动框架 BFS 查询管线的四区模型与 token_budget（写管线阶段② 依赖；两路径并存互为对照）。
- 不做跨 chat 的持久工作集（单次 chat 作用域；跨轮记忆走图——learn/search 本来就是）。
- 不引入独立的"上下文管理轮次"（管理决策 MUST 搭便车在既有回复上）。

## 关键设计决策

### D1：分层职责——模型排序、框架计数

| 职责 | 归属 | 机制 |
|---|---|---|
| 总量 ≤ 会话预算 | **框架** | 组装 messages 前逐条估算（估算 == 发送口径，会话层铁律一）；超限走 D3 兜底 |
| 留什么 / 换什么 | **模型** | pin 字段（D4）+ 显式换出 |
| 何时收尾 | **模型**（框架给信息） | 每轮注入「已用/剩余预算、剩余轮次」；max_turns 仍为保底 |

否决"模型自估 token"：LLM 数 token 不可靠（图层 1284 事故的会话层等价物）。

### D2：存根折叠（减脂层，先行落地）

- 规则：距当前 ≥ N 轮（默认 2）且未 pin 的 tool 消息 → 替换为单行存根：
  `[已折叠 #k] search("Sam Altman") → 12 节点: [id:a1f..], [id:9c3..], ...`
- 存根 id **窗口级去重**：每个触达节点 id 在窗口内只全文列一次（首次触达的存根行），后续存根对已见 id 以计数省略（如 `(+3 已见)`）——同一 id 列多份是纯浪费。**折叠 MUST NOT 丢弃窗口内尚未出现的 id**（丢了就是不可逆遗忘）；id 完整性是**窗口级**不变量而非单条存根级。D3 逐出（紧急路径）整条移除存根时其首见 id 随之出窗，可接受——框架台账仍全量、trace 记录、可按语义重查。
- **重复调用不拦截（去重做成信号，不做成机制）**：与窗口内存根同工具同参的再次调用 MUST NOT 被拒绝或返回缓存——相关性判断是**积累集依赖的**（第二跳证据可让第一遍看过的节点变得有意义；框架 BFS 的无条件 visited 硬去重正是 agent 路径要摆脱的弱点），且会话中 `learn` 会改图、缓存连正确性都不保证。框架检测到同参时 SHALL 在新结果头部标注一行（如 `（与存根 #2 同参）`）——"以前看过"是给模型的信号，重不重看由模型自决。
- assistant 消息与 user 消息不折叠（保推理连续性）；折叠在每轮组装时重算（幂等）——**原始 history 永不改写**，折叠 / 逐出均为组装期视图操作（pin 已折叠存根即恢复全文，取回零成本）。
- **无收益不折**：存根不比全文短就保留全文（优化判据：总量不降的重组无效，不做）——短结果折成存根反而更长且丢信息。
- 该层不依赖模型配合、无 prompt 改动，独立可 A/B——**先行验证减脂收益**。

### D3：确定性兜底（自治失败时的安全网）

超预算时框架按序执行：① 折叠所有可折叠项（含近轮）→ ② 逐出最旧未 pin 存根（**实现为一行墓碑 `[已逐出 #k]` 而非物理删除**——openai 格式要求 assistant 的每个 tool_call 有配对 tool 消息；trace 记录）→ ③ 仍超（pin 总量 > 预算）：拒绝本轮新工具结果注入（工具不执行）、向模型回一条 `[预算耗尽] 请换出 pin 项或收尾` 的 tool 消息——**该告知消息受保护、不折叠不逐出**（否则极端超预算时被兜底链吞掉，模型永远看不到指引；其本身 ~40 token、受 max_turns 有界）。MUST NOT 静默截断消息中段、MUST NOT 死锁（全部收敛手段用尽仍超时降级发送并记 overflow 事件）。

### D4：pin 语义（自治层）

- 约定：模型在工具调用的同轮回复文本尾部以固定标记声明（如 `PIN: #2 #5` / `UNPIN: #2`）——**不新增工具**（新增 pin 工具会花独立轮次，违背 Non-Goal）；框架解析标记、维护 pin 集。
- pin 项 = 软积累区（"已确认相关"）；默认上限占预算 70%（防 pin 囤积——这是唯一保留的"比例"，且是防御性上限而非分配比例，模型可在其内自由取舍）。
- 系统提示词补一段管理约定（何时 pin：已确认支撑答案的结果；何时不 pin：探索性搜索）。

### D5：预算注入与终止

每轮 system prompt 末尾追加一行动态段：`会话预算 12.3K/32K，剩余轮次 4`。收尾指令：预算或轮次将尽时，基于已 pin 内容作答（与封闭语料 prompt 的"探索充分后作答"衔接）。

### D6：显式终止语义（FINISH 收束）

- 现状的终止是**隐式**的：回复不含工具调用即被当作最终答复（`loop.py`）——无法区分"探索充分、主动收束"与"忘了调工具"。
- 约定：模型判断**无需再遍历**时，在最终回复中以固定标记声明（与 PIN 同族，如 `FINISH` + `USED: #2 #5`）；终止回复 MUST 携带它认为有用的东西——**最终答案 + 支撑证据引用**（存根/结果编号或节点 id，通常来自 pin 集）。终止即最终回复本身，不占独立轮次（与 D4 同一原则）。
- 框架行为：解析到 FINISH → 结束循环、剥离标记后返回答案；答案、支撑 id、终态 pin 集记入 trace（评测可直接取 reached / 出处）。
- **宽松解析**：无标记且无工具调用的回复**仍接受**为最终答复（不为格式合规浪费轮次），trace 记终止类型 `finish` / `implicit` / `finalized` / `forced`——A/B 观测 implicit 占比。
- 与 D5 衔接：预算/轮次将尽时的收尾指令即引导走 FINISH 路径（基于已 pin 内容作答）。随 `context_budget` 开启（默认关闭时不注入约定、不解析，零行为变化——D7）。
- **最后一轮指令 + 收尾轮**（200 题 A/B 实测 forced 率 0.64 后补强）：剩余 1 轮时预算段替换为「最后一轮请直接作答」；轮次仍耗尽未作答 → **收尾轮**：注入「立即交付」硬指令**有界 +1 调用**（工具调用被忽略），交付则记 `finalized`（forced 从「无答案失败」降级为「降级交付」）、仍无内容保持 `forced` 兜底。仅预算开启时生效（默认关闭无收尾轮，零行为变化）。
- **交付契约（评测/调用方层）**：FINISH 的 `USED:` 可被上层契约强化为「按相关性降序、上限 N 个来源」——给收束设**证据配额**（治过早自信收束：A/B 实测 finish 桶 reached 0.867 < forced 桶 0.990），并把模型相关性判断接进排序（bench 混合评分：USED 引用文档排前、词法 rerank 兜底补位）。框架只解析引用序列，不硬编码 N。

### D7：默认关闭，评测显式开启

`MemoryAgent(context_budget=None)` 保持现状（存量调用/测试零变化）；bench 显式传预算开启。A/B 赢了再讨论默认开启（另一次决策，不在本 change）。

## 验收 A/B（阶段门）

1. **阶段 A（仅 D2+D5，无 pin）**：黄金笼/multihop 各 30-50 题——token/题、超轮次失败、reached。预期 token 降 ≥40% 且 reached 持平（被折叠的多为死探索）。
2. **阶段 B（+D3+D4+D6 完整自治）**：同口径复测 + **盲目重复率**（同参重发且 pin 集自上次调用以来无变化的比率——积累集变化后的**有意重看**是 agent 优势而非故障，不计入震荡）+ implicit 终止占比（FINISH 约定遵从度）。
3. 任一阶段 reached 显著下降 → 停在上一阶段、修参再试（N 轮窗口 / pin 上限）。

## 被否决方案

- **模型自估 token 总量**：不可靠，见 D1。
- **同参调用拦截 / 返回缓存**：相关性判断是积累集依赖的、`learn` 会改图（见 D2）——去重做成信号不做成机制。
- **强制 FINISH 格式（无标记回复退回重问）**：多花一轮换格式合规，成本反噬；宽松解析 + trace 观测 implicit 占比足够。
- **pin 做成独立工具**：每次管理花一整轮（约 +19 次调用/题的基数上再加），成本反噬收益。
- **把 visited/frontier 台账全文放窗口**：id 簿记本来免费，进窗口纯浪费 T。
- **同步改造框架查询管线四区**：写管线阶段② 依赖其确定性行为；agent 路径先行、数据说话后再议（framework-to-agent-handoff 的既定节奏）。
- **跨 chat 持久工作集**：与"图即外置记忆"的架构命题重复——跨轮该进图的进图。
