## 二、查询（agent 导航）检索指标（非 null，n=130）

| 分组 | n | hit@2 | hit@4 | hit@10 | recall@10 | mrr@10 | recall@∞ |
|---|---|---|---|---|---|---|---|
| overall | 130 | 0.685 | 0.823 | **0.946** | 0.754 | 0.671 | 0.992 |
| inference_query | 50 | 0.760 | 0.920 | **1.000** | 0.793 | 0.769 | 0.990 |
| comparison_query | 45 | 0.556 | 0.667 | 0.889 | 0.744 | 0.550 | 0.989 |
| temporal_query | 35 | 0.743 | 0.886 | 0.943 | 0.710 | 0.686 | 1.000 |

- **召回天花板 reached = 1.000**：130 道非 null 题，agent 导航全部触达至少一篇 gold 场景。
- **recall@∞ = 0.992**：几乎所有 gold 场景都被触达——多子实体拆解 + jieba 字面种子在中文语料上非常有效。
- **主要损失在排序**：hit@2 0.685 → hit@10 0.946，说明词法 doc_rerank 排序是瓶颈，导航不是。
- comparison 最弱（hit@2 仅 0.556）：比较题要求两侧对象都召回且排前，词法排序对"另一侧"证据不友好。

## 三、null 题（封闭语料口径，n=20）

- **17/20（0.850）** 恰好回答 `Insufficient information.`；null 题平均触达 86.5 篇文档（agent 在无答案问题上探索充分而非直接放弃）。
- 3 个失败样例（各有代表性）：
  1. 「引线的物理熔断装置安装在哪个城市？」——达到 max_turns 未收尾（探索循环耗尽）；
  2. 「格里芬湖集会中头部流血的伤者叫什么名字？」——**真推理错误**：把简报中被拘留的马库斯误判为流血伤者（语料只说"有个人躺在地上，头上有血"，未具名）；
  3. 「委员会主席的姓名？」——语义上答对了"图中无姓名"（正确描述为塞内加尔人），但未按格式恰答一句，被严格口径判错。

## 五、结论与后续杠杆

1. **agent 建图可行且全自主**：0 强制补写；写入保真与 doc 溯源由评测侧 `BuildMemory` 钉死，
   agent 的修图工具（merge/split）在保守 prompt 下未被使用——后续可实验放宽修图边界，
   观察对图质量/检索的影响。
2. **导航近乎解决（reached 100%），排序是下一个杠杆**：词法 doc_rerank 之上可试
   LLM 重排或利用 agent 自身的相关性判断（它在回答时已经知道哪个场景是答案）。
3. **封闭语料 prompt 有效**（null 85%），残余失败是格式收尾与个别推理错，可在 prompt
   里补"实体必须逐字出自图中内容"约束。
4. 期间修复核心 bug：`MCS.query` 门面漏透传 `universe`（agent associate 对真实 MCS 必炸），
   见 `mcs/core/mcs.py` + `tests/test_mcs_api.py` 回归测试。
